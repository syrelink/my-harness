## 二、当前代码状态（重构后，重要）

- 用显式 `while` 循环实现 Agent Tool Loop，不再用 StateGraph / Checkpointer / ToolNode。
- 保留 `langchain`（`ChatOpenAI`、消息类型、`@tool`），只去掉了 `langgraph`。
- 会话状态用普通 dict + Postgres `agent_state` 表持久化（自写 `load_state`/`save_state`）。

## 五、讨论过的核心概念（面试要点，已对齐 2026 主流认知）

### Agent 工程四大支柱（对应简历四条）

1. **上下文管理（Context Engineering）**：token 是稀缺资源。近期原文 + 早期结构化摘要 + 图片引用降级。
2. **Skill 扩展（Agent Skills / 渐进式披露）**：能力模块化，三层按需加载（目录 → SKILL.md → references）。2026 主流是"单 Agent + Skill"而非多 Agent。
3. **响应性能优化**：串行改并行、动态路由、超时降级、结果裁剪、SSE 流式（TTFT）。
4. **Prompt 工程（评测驱动迭代）**：评测集 + A/B Test + bad case 定位。

### LangGraph 机制（用户已彻底理解）

- **checkpointer** = 仓库，**thread_id** = 抽屉号（分区键）。checkpointer 是接口，背后可以是内存/数据库。
- **Agent Loop**：ReAct（Agent ⇄ Tool）是最基础，还有 Planner-Executor、Supervisor、fan-out、Human-in-the-loop。
- **图 = 循环**：LangGraph 引擎底层就是 while 循环；节点=函数、边=调用顺序、条件边=if。
- **何时用框架**：只有需要并行/子图/人工介入/回滚时才值得；单 Agent 线性循环手写即可。

### 记忆体系

- **短期记忆**：滚动窗口（messages）+ 结构化摘要（context_summary）+ token 账本。
- **长期记忆**：向量库 + 语义检索，按需注入 prompt（项目目前没做，是潜在亮点）。
- LangGraph 里：短期用 checkpointer、长期用 Store；本质都是"外部持久化 + 按需注入"。

### 单 Agent vs 多 Agent

- 单 Agent + 多 Skill = 同一大脑换手册；多 Agent = 多个大脑互相发消息。
- 判据：子能力需不需要**自己的上下文和决策循环**。
- supervisor = 做路由的 Agent；意图识别 = 判断"用户想干什么"（选 skill、调不调工具、走哪条路都是意图识别）。

### 可观测性（三大支柱 + LLM 专属）

- **Logs**（离散事件）/ **Metrics**（聚合指标）/ **Traces**（单次调用链）。
- Langfuse 额外加 cost + evals；底层是 OpenTelemetry。
- Claude Code / Codex 用 OpenTelemetry 导出；模型 API（GPT/Claude）本身只返回 usage、不做 trace。
- DSH 内部 trace 实现未公开，但遵循"状态与日志分离"同一原则。

### 图片 Token 优化（用户纠结过的点，已讲清）

- 上传即存 OSS/MinIO，上下文只放 `attachment://id` 引用（省 token、可鉴权、不过期、解耦）。
- 当前轮需要看图才按 id 取回、临时还原，不写回状态。
- URL 是"临时取用物"，id 是"持久占位符"；本地 CLI Agent（Codex/DSH）用文件路径当占位符。

## 七、性能分析（71 秒 trace，待优化）

文件：`trace/trace-a652676309411b127b3f95687b00dfa0.json`

| 阶段 | 耗时 | 占比 |
|---|---|---|
| ① 模型判断→调 skill | 4.80s | 7% |
| ② skill 加载（本地） | 0.00s | 0% |
| ③ 模型→调 web_search | 13.90s | 20% |
| ④ DuckDuckGo 搜索 | 1.53s | 2% |
| ⑤ **模型生成最终回答** | **50.70s** | **71%** |

**根因**：
1. `mimo-v2.5` 是推理模型，最后一轮输出 961 正文 + 323 reasoning token（"思考税"），速度 ~25 tok/s。
2. ReAct 串行 3 次模型调用。
3. 第 ③ 步搜索对"开荒路线"这种稳定知识是冗余的（skill 触发条件太宽）。

**待办优化**：
- 换更快模型（`.env` 里 `GAME_ASSISTANT_MODEL` 试 `deepseek-chat`）。
- 收紧 `gameplay-guide` SKILL.md 的搜索触发条件。
